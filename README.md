# Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Учебный интернет-магазин «Перекупы 1С». Основа перенесена из проекта
контрольной работы №1 `kr1-html-css-shop`. Используются HTML, CSS и JavaScript
без Bootstrap, сборки и внешних зависимостей.

Рекомендуемое имя удалённого репозитория: `kr3-responsive-shop`.
Локальная папка проекта: `kr3`.

## Запуск

Откройте `index.html` в браузере или запустите локальный сервер из папки проекта:

```bash
python -m http.server 8000
```

После запуска сервера откройте `http://localhost:8000`.

## Назначение файлов

- `index.html` — главная страница, товары, отзывы и модальное окно заявки.
- `catalog.html` — каталог с блоком фильтров.
- `product.html`, `product-2.html`, `product-3.html` — страницы трёх товаров с таблицами характеристик.
- `order.html` — отдельная страница заявки.
- `contacts.html` — контактная информация.
- `css/style.css` — исходные стили КР №1: оформление, переменные и компоненты.
- `css/responsive.css` — файл для адаптации по подходу Mobile First; подключён после `style.css` на всех семи страницах.
- `js/main.js` — мобильная навигация, модальное окно, выбор товара и клиентская проверка формы.
- `images/` — исходные фотографии, уменьшенные копии для карточек и три варианта hero-изображения.

### Адаптивные изображения: этапы 12–14

Для карточек подготовлены уменьшенные JPEG-копии шириной 240 и 320 px;
для третьего товара также 480 и 640 px. Самые большие кандидаты — исходные
фотографии шириной 440, 395 и 800 px соответственно. Дескрипторы `w`
совпадают с фактической шириной файлов. Исходники сохранены;
увеличение их разрешения не выполнялось.

`sizes` учитывает боковые отступы страницы, промежутки сетки, внутренние
отступы карточек, максимальную ширину контейнера и боковой фильтр каталога.
Формулы на главной и в каталоге различаются, поскольку различается число
колонок и доступное им место. Размеры остаются приблизительными из-за
разной ширины полосы прокрутки в браузерах.

В hero используются три версии фотографии калькулятора: 320 × 240,
400 × 400 и 440 × 454 px. Товар вписан целиком в белый фон без обрезки
и искажения пропорций. Hero загружается без `loading="lazy"`.

В Edge выполнены 44 проверки: главная и каталог на ширинах 360, 430, 640,
768, 900, 1024, 1199, 1200, 1232, 1280 и 1440 px при DPR 1 и 2.
Проверены реальные запросы изображений через DevTools Protocol,
`currentSrc`, загрузка файлов, пропорции карточек и соответствие `sizes`
отрисованной ширине. На 360 px при DPR 1 карточки используют версии 320 px;
hero переключается между мобильным, планшетным и desktop-файлом.
Переполнения страницы и ошибок загрузки не обнаружено.

### Итоговая визуальная проверка и исправления

Все семь страниц просмотрены по снимкам браузера Edge в мобильной,

- мобильная шапка занимала 409 px до начала содержимого — добавлено раскрывающееся меню; закрытая шапка занимает 77 px;
- на широком экране шапка занимала 145 px — логотип и навигация размещены в одну строку от 1200 px, высота стала 97 px;
- убраны двойные вертикальные отступы разделов;
- три товара на главной заполняют строку без пустой четвёртой колонки; `sizes` приведён к фактической ширине карточек;
- кнопка «Наверх» встроена в подвал вместо отдельной белой полосы;
- отключено закрепление шапки на низких экранах;
- заблокирована прокрутка страницы под модальным окном, устранён сдвиг содержимого при его открытии;
- обновлены устаревшие вводные тексты, обещавшие уже реализованные блоки.

После исправлений повторно выполнены 49 проверок всех страниц на ширинах
